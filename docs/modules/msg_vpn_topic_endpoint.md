| `delivery_count_enabled` | boolean | No | `False` | Enable or disable the ability for client applications to query the message delivery count of messages received from the Topic Endpoint. This is a controlled availability feature. Please contact support to find out if this feature is supported for your use case. |
| `delivery_delay` | integer | No | `0` | The delay, in seconds, to apply to messages arriving on the Topic Endpoint before the messages are eligible for delivery. |
| `egress_enabled` | boolean | No | `False` | Enable or disable the transmission of messages from the Topic Endpoint. |

| `event_spool_usage_threshold` | object | No | - |  |

| `max_bind_count` | integer | No | `1` | The maximum number of consumer flows that can bind to the Topic Endpoint. |
| `max_delivered_unacked_msgs_per_flow` | integer | No | `10000` | The maximum number of messages delivered but not acknowledged per flow for the Topic Endpoint. |
| `max_msg_size` | integer | No | `10000000` | The maximum message size allowed in the Topic Endpoint, in bytes (B). |
| `max_redelivery_count` | integer | No | `0` | The maximum number of times the Topic Endpoint will attempt redelivery of a message prior to it being discarded or moved to the DMQ. A value of 0 means to retry forever. |
| `max_spool_usage` | integer | No | `5000` | The maximum message spool usage allowed by the Topic Endpoint, in megabytes (MB). A value of 0 only allows spooling of the last message received and disables quota checking. |
| `max_ttl` | integer | No | `0` | The maximum time in seconds a message can stay in the Topic Endpoint when `respectTtlEnabled` is `"true"`. A message expires when the lesser of the sender assigned time-to-live (TTL) in the message and the `maxTtl` configured for the Topic Endpoint, is exceeded. A value of 0 disables expiry. |
| `owner` | string | No | - | The Client Username that owns the Topic Endpoint and has permission equivalent to `"delete"`. Changing this may briefly interrupt the affected service. |
| `permission` | string | No | `no-access` | The permission level for all consumers of the Topic Endpoint, excluding the owner. Changing this may briefly interrupt the affected service. (`no-access`, `read-only`, `consume`, `modify-topic`, `delete`) |
| `redelivery_delay_enabled` | boolean | No | `False` | Enable or disable a message redelivery delay. When false, messages are redelivered as-soon-as-possible. When true, messages are redelivered according to the initial, max and multiplier. This should only be enabled when redelivery is enabled. Changing this may briefly interrupt the affected service. |
| `redelivery_delay_initial_interval` | integer | No | `1000` | The delay to be used between the first 2 redelivery attempts. This value is in milliseconds. Changing this may briefly interrupt the affected service. |
| `redelivery_delay_max_interval` | integer | No | `64000` | The maximum delay to be used between any 2 redelivery attempts. This value is in milliseconds. Due to technical limitations, some redelivery attempt delays may slightly exceed this value. Changing this may briefly interrupt the affected service. |
| `redelivery_delay_multiplier` | integer | No | `200` | The amount each delay interval is multiplied by after each failed delivery attempt. This number is in a fixed-point decimal format in which you must divide by 100 to get the floating point value. For example, a value of 125 would cause the delay to be multiplied by 1.25. Changing this may briefly interrupt the affected service. |
| `redelivery_enabled` | boolean | No | `True` | Enable or disable message redelivery. When enabled, the number of redelivery attempts is controlled by maxRedeliveryCount. When disabled, the message will never be delivered from the topic-endpoint more than once. |
| `reject_low_priority_msg_enabled` | boolean | No | `False` | Enable or disable the checking of low priority messages against the `rejectLowPriorityMsgLimit`. This may only be enabled if `rejectMsgToSenderOnDiscardBehavior` does not have a value of `"never"`. |
| `reject_low_priority_msg_limit` | integer | No | `0` | The number of messages of any priority in the Topic Endpoint above which low priority messages are not admitted but higher priority messages are allowed. |
| `reject_msg_to_sender_on_discard_behavior` | string | No | `never` | Determines when to return negative acknowledgments (NACKs) to sending clients on message discards. Note that NACKs cause the message to not be delivered to any destination and Transacted Session commits to fail. Changing this may briefly interrupt the affected service. (`never`, `when-topic-endpoint-enabled`, `always`) |
| `respect_dmq_eligible_enabled` | boolean | No | `False` | Enable or disable the respecting of DMQ Eligible for messages in the Topic Endpoint. |
| `respect_msg_priority_enabled` | boolean | No | `False` | Enable or disable the respecting of message priority. When enabled, messages contained in the Topic Endpoint are delivered in priority order, from 9 (highest) to 0 (lowest). Changing this may briefly interrupt the affected service. |
| `respect_ttl_enabled` | boolean | No | `False` | Enable or disable the respecting of the time-to-live (TTL) for messages in the Topic Endpoint. When enabled, expired messages are discarded or moved to the DMQ. |
| `msg_vpn_name` | string | No | - | Message VPN to act on. Defaults to the VPN in the connection config. |
